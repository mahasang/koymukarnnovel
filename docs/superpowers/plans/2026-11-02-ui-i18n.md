# Public UI Three-Language (th/en/lo) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Readers of the public site can switch the UI between ไทย, English and ລາວ; novel content stays Thai.

**Architecture:** A hand-written typed message tree (`web/src/i18n/th.ts` is the source of truth; `en.ts`/`lo.ts` must match its type) exposed through `useI18n()`. Pure lib functions that return UI text take the message tree as a parameter. A ratchet test lists the files that still contain Thai literals; each task converts its files and removes them from the list. The admin tree is wrapped in a provider fixed to Thai.

**Tech Stack:** React 19, react-router, TypeScript, `node:test` + tsx (web tests are SSR-rendered with `testing/render.tsx`), `@fontsource/noto-sans-lao`, Playwright e2e (`e2e/run.mjs`).

**Spec:** `docs/superpowers/specs/2026-11-01-ui-i18n-design.md`

## Global Constraints

- Locales are exactly `"th" | "en" | "lo"`; default `th`; saved choice key `koymukarnnovel.lang` (add `lang` to `KEYS` in `web/src/lib/storage.ts`; storage access must never throw).
- Order of choice: saved value → first `navigator.languages` entry starting with `th`/`lo`/`en` → `th`.
- No new i18n library. Message functions take only numbers or strings; English plurals live inside the function.
- Digits are Arabic (0–9) in every language. Dates are shown in UTC+7. Year: Thai = พ.ศ. (`+543`, unchanged output "22 ต.ค. 2569"); English and Lao = ค.ศ. Lao months: ມັງກອນ ກຸມພາ ມີນາ ເມສາ ພຶດສະພາ ມິຖຸນາ ກໍລະກົດ ສິງຫາ ກັນຍາ ຕຸລາ ພະຈິກ ທັນວາ.
- Content stays Thai and carries `lang="th"` (use `CONTENT_LANG` from `i18n/types.ts`): novel titles, chapter titles, authors, tags, synopsis, chapter text, and site name/tagline/about/contact text.
- Admin (`web/src/admin/**`) is never translated and always renders Thai (`<I18nProvider fixedLocale="th">`); `admin/dashboard-logic.ts` keeps using `thaiDate`.
- Server (meta/OG/sitemap/API messages) is not changed.
- New file names must not differ from an existing name only by letter case (`web/src/layout.test.ts` enforces this on Windows-safe naming).
- Font: `@fontsource/noto-sans-lao`, subset `lao`, weights 400/500/600/700 only, appended after Sarabun/Prompt in `--font-body` and `--font-ui`.
- Gate for every task: `npm run typecheck`, `npm test` (root) green; before the last task also `npm run build`.

## Review Focus

1. Saved language value is garbage (`"fr"`, `"{}"`), storage throws, or `navigator.languages` is empty/undefined → Thai, no throw (Task 1).
2. A Lao-UI reader sees Thai novel text and site texts; `lang="th"` wraps them so font/segmentation are correct (Tasks 5–7).
3. A server error whose `code` is not in the table still shows the server's Thai message, with the hint in the reader's language (Task 3).
4. Reader chose Lao, then opens `/admin`: admin stays Thai and the saved choice is not overwritten (Task 1, Task 9).
5. Lao strings are longer/taller than Thai: no horizontal scroll or clipped buttons/chips at 390px (Task 9).

## Conversion recipe (used by Tasks 3–7)

For each file in the task: move every Thai UI literal (text, `aria-label`, `title`, `placeholder`, `alt`) into the task's message namespace in `th.ts` (value identical to today's text), add `en.ts` and `lo.ts` entries (Claude drafts; keep Lao natural, not word-for-word), read them through `const { m } = useI18n()`, remove the file from `PENDING` in the guard test, keep existing Thai assertions passing unchanged. A test per task renders the touched component with `renderPage(node, { locale: "lo" })` and asserts a Lao string appears and the Thai one does not.

### Task 1: i18n core, provider, guard ratchet

**Files:**

- Modify: `web/src/lib/storage.ts` (add `KEYS.lang`), `web/src/App.tsx`, `web/src/testing/render.tsx`

**Interfaces:**
- Produces (`types.ts`): `LOCALES`, `type Locale`, `DEFAULT_LOCALE: Locale`, `LOCALE_NAMES: Record<Locale,string>` (`ไทย`/`English`/`ລາວ`), `CONTENT_LANG = "th"`.
- Produces (`detect.ts`): `isLocale(v: unknown): v is Locale`, `detectLocale(languages: readonly string[] | undefined): Locale | null`, `initialLocale(saved: unknown, languages: readonly string[] | undefined): Locale`.
- Produces (`apply.ts`): `applyLocale(doc: { documentElement: { lang: string } }, locale: Locale): void` (sets `lang`), `loadLocale(): Locale` (= `initialLocale(readJson(KEYS.lang, null), navigator?.languages)`, safe when `navigator` is missing), `saveLocale(locale: Locale): void` (via `writeJson`); neither throws.
- Produces (`th.ts`): `export const th = { lang: { menuLabel: "ภาษา" }, … }`; (`messages.ts`): `export type Messages = typeof th`, `export const MESSAGES: Record<Locale, Messages>`. `en.ts`/`lo.ts` are annotated `: Messages`.
- Produces (`I18nProvider.tsx`): `I18nProvider({ children, fixedLocale }: { children: ReactNode; fixedLocale?: Locale })`, `useI18n(): { locale: Locale; m: Messages; setLocale(l: Locale): void }`. Outside a provider `useI18n()` returns Thai and a no-op `setLocale`. With `fixedLocale`, `setLocale` is a no-op and nothing is saved or applied to `<html>`.
- Produces (`render.tsx`): `renderPage(node, { path?, state?, locale? })` wraps in `<I18nProvider fixedLocale={locale}>` when `locale` is given.
