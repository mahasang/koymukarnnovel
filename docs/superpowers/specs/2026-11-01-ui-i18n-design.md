- วันที่: 2026-11-01

- ต่อยอดจาก `2026-10-22-koymukarnnovel-admin-reader-design.md` (ฉบับ 2.1) · ฐานโค้ด: `main` @ `61def29`

## 1. เป้าหมายและขอบเขต

**เป้าหมาย:** ผู้อ่านเว็บสาธารณะเลือกให้เมนูและข้อความบนหน้าจอเป็นไทย อังกฤษ หรือลาวได้ เพื่อให้ผู้อ่านชาวลาวและต่างชาติใช้เว็บได้สะดวก

**ที่เจ้าของยืนยันแล้ว (2026-11-01):**

1. UI ของ **หน้าบ้านสาธารณะอย่างเดียว** (หลังบ้านคงเป็นไทย)
2. เนื้อนิยาย (ชื่อ เรื่องย่อ คำแปลตอน) **เป็นไทยอย่างเดียว** ภาษาอื่นเพิ่มทีหลังเป็นงานแยก
3. เสียงอ่านคงภาษาไทยก่อน ภาษาอื่นเพิ่มวันหลัง
4. ภาษาเริ่มต้นตามภาษาเบราว์เซอร์ ไม่ตรง → ไทย จำค่าที่ผู้อ่านเลือก URL ไม่เปลี่ยน
5. ปีในวันที่ของ **ภาษาอังกฤษและลาวใช้ ค.ศ.**
6. ข้อความลาว/อังกฤษ Claude ร่าง เจ้าของ (อ่านลาวได้) ตรวจแก้ก่อนใช้จริง

**ไม่ทำในรอบนี้:** UI หลังบ้าน, เสียงอ่านภาษาอื่น, คำแปลนิยายหลายภาษา (ตาราง/API/prompt), Google Translate หรือการลดต้นทุนโทเคน (เรื่องแยก), meta/OG/sitemap ฝั่งเซิร์ฟเวอร์ (ยังเป็นไทย)

**ข้อสันนิษฐานที่ขอให้ตรวจ:** ผมตีความ "ปี ค.ศ. สากล" ว่าใช้กับอังกฤษและลาว ส่วน **ไทยคง พ.ศ. ตามเดิม** (เช่น "22 ต.ค. 2569") ถ้าต้องการให้ไทยใช้ ค.ศ. ด้วย แก้ที่ตารางรูปแบบวันที่จุดเดียว (หัวข้อ 4.4)

## 2. โครงสร้าง

```
web/src/i18n/
  types.ts        Locale = "th" | "en" | "lo";  interface Messages (ต้นแบบของรูปร่างข้อความ)
  th.ts           ข้อความไทย (ค่าเดิมในโค้ดย้ายมาไว้ที่นี่)   : Messages
  en.ts           ข้อความอังกฤษ                               : Messages
  lo.ts           ข้อความลาว (ร่างโดย Claude รอเจ้าของตรวจ)    : Messages
  I18nProvider.tsx  state ภาษา, อ่าน/เขียน localStorage, ตั้ง <html lang>
  detect.ts       เลือกภาษาเริ่มต้นจาก navigator.languages (ฟังก์ชันบริสุทธิ์)
```

- **ใช้อ็อบเจ็กต์ข้อความ ไม่ใช้สตริงคีย์:** `const { m } = useI18n(); m.header.search` ข้อความที่มีพารามิเตอร์เป็นฟังก์ชัน เช่น `m.time.minutesAgo(5)` ทำให้ TypeScript จับข้อความที่ขาดหรือพารามิเตอร์ผิดได้ตอน compile และจัดการรูปพหูพจน์ของอังกฤษในฟังก์ชันได้ ("1 chapter" / "2 chapters") ไทยและลาวไม่มีพหูพจน์
- **`useI18n()` นอก provider คืนภาษาไทย (ไม่ throw)** เพื่อให้เทสต์คอมโพเนนต์เดิมที่ไม่ห่อ provider ยังผ่านโดยไม่แก้
- ฟังก์ชันบริสุทธิ์ใน `lib/` ที่คืนข้อความไทยตอนนี้ (เช่น `timeAgo`, `thaiDate`, ตัวสร้างข้อความรายการตอน/ห้องสมุด, `errorHint`) **รับ `m: Messages` (หรือ locale) เป็นพารามิเตอร์** เทสต์ของฟังก์ชันเหล่านี้ต้องแก้ให้ส่ง `th` เข้าไป ค่าที่ assert เป็นข้อความไทยชุดเดิมไม่เปลี่ยน
- ข้อความที่ใช้เฉพาะหลังบ้าน (`lib/parse-chapters.ts`, `lib/cover-crop.ts`, `lib/cost.ts` ฯลฯ และทุกไฟล์ใต้ `web/src/admin/`) **ไม่แตะ**

## 3. การเลือกภาษาและสลับภาษา

1. **ลำดับ:** ค่าที่จำไว้ (`koymukarnnovel.lang` ใน localStorage) → `navigator.languages` ตัวแรกที่ขึ้นต้น `th` / `lo` / `en` → ไทย
2. อ่าน/เขียน localStorage ห่อ try/catch เหมือนที่เก็บอื่น (หัวข้อ 6.7 ของ spec หลัก) ใช้ไม่ได้ก็ใช้ค่าตรวจจับและไม่จำ
3. state เริ่มต้นอ่านแบบ sync ก่อนวาดหน้าแรก และตั้ง `document.documentElement.lang` ทันทีที่ภาษาเปลี่ยน (shell จากเซิร์ฟเวอร์เป็น `lang="th"`) จึงไม่มีจังหวะที่ UI เป็นภาษาหนึ่งแต่ `lang` เป็นอีกภาษา
4. **ปุ่มสลับ:** เมนูเล็กใน Header ใกล้ปุ่มธีม ตัวเลือก "ไทย / English / ລາວ" ชื่อภาษาแสดงเป็นภาษาตัวเองเสมอ ทำตามรูปแบบ `ThemeMenu` (รองรับคีย์บอร์ดและ focus เหมือนกัน)
5. **หลังบ้านบังคับไทย:** `I18nProvider` รับ prop `fixedLocale` ส่วนหลังบ้านครอบด้วย `fixedLocale="th"` เพื่อให้คอมโพเนนต์ที่ใช้ร่วม (ConfirmDialog, Switch ฯลฯ) ไม่เป็นลาวในหน้าที่ที่เหลือเป็นไทย การเลือกภาษาของผู้อ่านไม่ถูกเขียนทับ

## 4. สิ่งที่แปล และสิ่งที่ไม่แปล

### 4.1 แปล
ข้อความคงที่ในหน้าบ้าน: Header/Footer/ค้นหา, หน้าแรก (Hero, อ่านต่อ, อัปเดตล่าสุด, ตัวกรอง/เรียง, ปุ่มแสดงเพิ่ม), หน้าเรื่อง (ปุ่ม, กล่องเครดิต, รายการตอน), หน้าอ่าน (แถบบน, ตั้งค่าการอ่าน, ปุ่มก่อนหน้า/ถัดไป, ปุ่มฟังเสียงและข้อความอธิบาย), หน้า 404, สถานะ โหลด/ผิดพลาด/ว่าง, ป้ายร่าง, ชื่อธีม, `aria-label`/`title` ทั้งหมด และ `AppErrorBoundary`

### 4.2 ข้อความ error จากเซิร์ฟเวอร์
เซิร์ฟเวอร์ตอบ `{error, code}` (ข้อความไทย + รหัส) ฝั่งเว็บมีตารางรหัส→ข้อความต่อภาษาสำหรับรหัสที่หน้าบ้านพบได้ (เช่น `not_found`, `rate_limited`, `internal_error`, `method_not_allowed`) ถ้า `code` ไม่อยู่ในตาราง แสดง `error` ไทยตามเดิม คำแนะนำใต้ error (`errorHint`) แปลตามภาษา

### 4.3 ไม่แปล (เป็นเนื้อหา ไม่ใช่ UI)
ชื่อเรื่อง/ชื่อตอน/ผู้แต่ง/แท็ก/เรื่องย่อ/คำแปลตอน และข้อความที่เจ้าของกรอกในหลังบ้าน (ชื่อเว็บ สโลแกน เกี่ยวกับ ติดต่อ) จึงขึ้นเป็นไทยแม้ UI เป็นลาว/อังกฤษ **ใส่ `lang="th"` ที่กรอบของเนื้อหาเหล่านี้** เพื่อให้ฟอนต์ การตัดคำ และตัวอ่านหน้าจอเลือกถูก และไม่ให้ `lang` ของหน้าทำให้เบราว์เซอร์เลือกฟอนต์สำรองผิด

### 4.4 วันที่ เวลา และตัวเลข
- `thaiDate(sql)` เปลี่ยนเป็น `formatDate(sql, locale)` คงการแสดงเป็นเวลา UTC+7 (ลาวอยู่โซนเดียวกัน) และคืนสตริงว่างเมื่อรูปแบบผิดเหมือนเดิม

| ภาษา | รูปแบบ | ตัวอย่าง |
|---|---|---|
| ไทย | วัน เดือนย่อ พ.ศ. | 22 ต.ค. 2569 (เหมือนเดิม) |
| English | วัน เดือนย่อ ค.ศ. | 22 Oct 2026 |
| ລາວ | วัน เดือนลาว ค.ศ. | 22 ຕຸລາ 2026 |

- ชื่อเดือนลาว: ມັງກອນ ກຸມພາ ມີນາ ເມສາ ພຶດສະພາ ມິຖຸນາ ກໍລະກົດ ສິງຫາ ກັນຍາ ຕຸລາ ພະຈິກ ທັນວາ
- **ตัวเลขใช้เลขอารบิก (0–9) ทุกภาษา** รวมภาษาลาว (ไม่ใช้เลขลาว ໑໒໓) เพื่อให้ตรงกับคำแปลนิยายและเลขตอน
- ป้ายเวลา (`timeAgo`) ตรรกะเดิมทั้งหมด เปลี่ยนเฉพาะข้อความที่ประกอบจาก `m.time.*`

## 5. ฟอนต์

- Sarabun/Prompt ไม่มีอักษรลาว จึงเพิ่ม `@fontsource/noto-sans-lao` (subset `lao`, น้ำหนัก 400/500/600/700 เท่าที่ใช้) และต่อท้ายลำดับ `--font-body` / `--font-ui` หลัง Sarabun/Prompt ก่อน `system-ui`
- CSS ของ `@fontsource` ใช้ `unicode-range` เบราว์เซอร์ดาวน์โหลดไฟล์ลาวเมื่อบนหน้ามีอักษรลาวจริงเท่านั้น ผู้อ่านไทยและอังกฤษไม่ต้องโหลดเพิ่ม
- ไม่เพิ่มฟอนต์ลาวสำหรับโหมดอ่าน (เนื้อหายังเป็นไทย)
- ต้องตรวจให้ service worker ยัง precache/cache-first ไฟล์ฟอนต์ใหม่ตามนโยบายเดิม (ไฟล์ที่มี hash)
- ต้องตรวจจริงว่าอักษรลาวไม่ถูกตัดบรรทัดผิดและไม่ล้นปุ่ม/ชิป/การ์ด (ข้อความลาวมักยาวต่างจากไทย)

## 6. การทดสอบ

1. **ความครบของข้อความ:** ทุกภาษามีรูปร่างเดียวกับ `Messages` (เทียบโครงสร้างแบบ recursive) ฟังก์ชันข้อความถูกเรียกด้วยค่าตัวอย่างและต้องได้สตริงไม่ว่างที่มีค่าพารามิเตอร์ตัวเลขอยู่ในนั้น
2. **ไม่มีข้อความไทยหลงในไฟล์ UI หน้าบ้าน:** เทสต์สแกน `web/src/pages`, `web/src/components` และไฟล์ `lib/` ที่ใช้กับหน้าบ้าน (ไม่นับคอมเมนต์ไฟล์ทดสอบ และ `i18n/`) แล้วล้มถ้าพบอักษรไทยในสตริงลิเทอรัล/JSX มีรายการยกเว้นที่เขียนเหตุผลกำกับ (เช่น ชื่อ "ไทย" ในเมนูภาษา) เพื่อกันลืมแปลตอนเพิ่มฟีเจอร์ภายหลัง (วิธีเดียวกับ `layout.test.ts`)
3. **ตรวจจับภาษา:** `detect` ครอบคลุม `th-TH`, `lo-LA`, `en-US`, `th` ปนกับอื่น, ลำดับความสำคัญ, ค่าที่จำไว้ชนะ, ค่าที่จำไว้ไม่ถูกต้อง → ตรวจจับใหม่, localStorage ใช้ไม่ได้
4. **provider:** เปลี่ยนภาษาแล้วข้อความและ `<html lang>` เปลี่ยนพร้อมกัน, `fixedLocale` ไม่ถูกกระทบโดยการเลือกของผู้อ่าน, ไม่มี provider → ไทย
5. **วันที่/เวลา:** ทั้งสามภาษา รวมกรณีขอบเดิม (รูปแบบผิด, เวลาในอนาคต, เมื่อวาน, ≥ 30 วัน)
6. **e2e (Chromium จริง):** สลับเป็นลาวและอังกฤษที่ 390px และ 1280px เก็บภาพ ตรวจว่าไม่มีแถบเลื่อนแนวนอน ภาษาถูกจำหลังรีโหลด และหลังบ้านยังเป็นไทยแม้ผู้อ่านเลือกลาว
7. เทสต์เดิมทั้งหมด (3007) ต้องยังผ่าน หลังแก้ลายเซ็นฟังก์ชัน `lib/` ตามหัวข้อ 2

## 7. การตัดสินใจและข้อแลกเปลี่ยน

| เรื่อง | ที่เลือก | ถ้าผิดเสียอะไร |
|---|---|---|
| ไลบรารี | เขียนเอง (อ็อบเจ็กต์ข้อความ + hook) ไม่ใช้ i18next | ถ้าจะเพิ่มภาษาที่มีพหูพจน์ซับซ้อนมากภายหลัง ต้องเขียนฟังก์ชันเพิ่ม หรือย้ายไปไลบรารี |

| URL | ไม่มี prefix ภาษา | แชร์ลิงก์แล้วภาษาตามเครื่องผู้เปิด ไม่ใช่ตามผู้ส่ง SEO หลายภาษาทำไม่ได้ (ยอมรับ เพราะเนื้อหายังเป็นไทย) |
| meta/OG | คงไทย | พรีวิวลิงก์เป็นไทยเสมอ |
| ตัวเลข | เลขอารบิกทุกภาษา | ผู้อ่านลาวบางคนอาจชอบเลขลาว (เปลี่ยนได้ในฟังก์ชันจัดรูปแบบจุดเดียว) |
| ปี | ไทย พ.ศ. · อังกฤษ/ลาว ค.ศ. | ดูหัวข้อ 1 |
| ข้อความลาว | Claude ร่าง เจ้าของตรวจ | อาจแข็งหรือผิดสำนวนจนกว่าเจ้าของแก้ รวมไว้ที่ `lo.ts` ไฟล์เดียว |

## 8. ความเสี่ยง

- ข้อความลาวและอังกฤษที่ผมเขียนยังไม่ผ่านผู้พูดภาษานั้นจริงจนกว่าเจ้าของตรวจ ลาวมีความเสี่ยงสูงสุด
- การแก้ลายเซ็นฟังก์ชัน `lib/` แตะหลายจุด ต้องไล่ทุกผู้เรียก (typecheck ช่วยจับ)
- ข้อความลาวที่ยาวกว่าอาจดันเลย์เอาต์บนมือถือ ต้องดูภาพจริง
- รันบน Windows ของเจ้าของไม่ได้จากที่ทำงานของ Claude (ปัญหาตัวพิมพ์เล็ก/ใหญ่ของชื่อไฟล์ถูกกันไว้ด้วย `layout.test.ts` แล้ว ไฟล์ใหม่ใน `i18n/` ใช้ชื่อตัวพิมพ์เล็กล้วนหรือ PascalCase ที่ไม่ชนกัน)
